# Decision Contract — [案例名称]

## 输入与结构化输出

| 项目 | 合同 |
| --- | --- |
| 输入 | `[允许的数据类型、脱敏要求、长度与完整性限制]` |
| 输出 | `decision`、`status`、`critical_gap`、`manual_review`、`citation`，以及本案例定义的版本与解释字段 |
| 证据 | 每项结论必须关联可定位的来源片段；无证据时输出未知/待复核，不得补造 |

## 职责边界

| 主体 | 可以做 | 不可以做 |
| --- | --- | --- |
| LLM | 提取、归纳、候选匹配、解释、引用候选 | 拥有不可逆或高风险的最终授权；编造事实或证据 |
| 确定性规则 | 校验 Schema、版本、输入约束、明确业务 Gate、降级 | 将未定义的业务判断伪装成确定性结论 |
| 人工 | 复核高风险项、处理冲突、批准最终行动、更新规则 | 以未留痕的判断替代证据 |

## 错误降级

- 输入缺失、输出不合规、引用失效、冲突或模型不可用：返回安全状态，标记 `manual_review: true`，保留原因码。
- 本案例应定义 `critical_gap` 的触发条件、优先级和责任人；模板不预设其业务含义。
- LLM 不应拥有不可逆或高风险的最终授权。

## 验收

- [ ] 输出字段及允许枚举已定义并可自动校验。
- [ ] 每个关键 Gate 有正反例、待确认例或异常例。
- [ ] 人工复核队列、引用定位方式和升级路径已定义。
