# Test Plan — Phase 2 / 3

## 必须顺序

1. **Preflight**：确认 Key 仅以存在状态检查、API 地址、`/parameters`/`/info` 可访问，以及已发布输入与契约一致。
2. **Smoke（3–5 条）**：最小覆盖阻断、无效输入、合规主链；仅断言终端分支和稳定字段。
3. **全量 Golden Set**：使用已审阅、脱敏的样本，逐条记录输入版本、预期、实际结构化输出、人工审阅与失败分类。
4. **关键用例重复运行**：比较分支、状态、结构、Lineage 与证据引用；不以 LLM 自由文本完全一致为条件。
5. **Evidence**：仅从真实运行派生证据包，注明样本范围、失败与未验证项。

## 记录与通过

每次运行记录快照 SHA、Dify 可得标识、样本 ID/版本、终端分支、断言、人工动作、错误与时间；不记录密钥或完整敏感输入。任一解析/Gate/分支/人工留痕不符即失败，保留首轮事实，不用逻辑重跑覆盖。
